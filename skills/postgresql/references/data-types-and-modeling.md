# PostgreSQL — Data Types & Modeling

## Picking types

| Category | Recommended | Avoid |
|---|---|---|
| Integer ID | `bigint` + `GENERATED ALWAYS AS IDENTITY` (or `uuid` + `uuidv7()` in PG18) | `serial` (legacy) |
| Text | `text` | `varchar(n)` unless you want the length CHECK |
| Money / decimal | `numeric(p, s)` | `float`, `double precision` |
| Boolean | `boolean` | `int 0/1` |
| Time | `timestamptz` | `timestamp` (without time zone), `time` |
| JSON | `jsonb` | `json` (no indexes, no operators) |
| Binary | `bytea` | base64-encoded `text` |
| UUID | `uuid` (`uuidv7()` PG18+) | `text` storing UUID strings |
| Enum | `CREATE TYPE x AS ENUM (...)` | small `text` + CHECK if values change often |
| Array | `int[]`, `text[]` | comma-separated string |
| IP | `inet`, `cidr` | `text` |
| Range | `int4range`, `tstzrange` | composite (a, b) + manual checks |

## Identity columns (PG10+)

```sql
CREATE TABLE users (
  id    bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  email text NOT NULL
);
```

`GENERATED ALWAYS` blocks explicit insertion of IDs (safer). `GENERATED BY DEFAULT` allows it (needed for restore/migration).

## UUIDv7 (PG18)

```sql
CREATE TABLE orders (
  id          uuid PRIMARY KEY DEFAULT uuidv7(),
  ...
);
```

`uuidv7()` is timestamp-ordered → B-tree index stays compact (no page splits on inserts). Replaces the `cuid()` workaround.

## Constraints

```sql
CREATE TABLE orders (
  id         uuid PRIMARY KEY DEFAULT uuidv7(),
  user_id    uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  amount     numeric(10,2) NOT NULL,
  currency   char(3) NOT NULL,
  status     text NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),

  CONSTRAINT positive_amount CHECK (amount > 0),
  CONSTRAINT iso_currency    CHECK (currency = upper(currency) AND length(currency) = 3),
  CONSTRAINT valid_status    CHECK (status IN ('pending', 'paid', 'refunded', 'canceled'))
);
```

Add a `CHECK` constraint **before** filling the table — Postgres will validate existing rows when `CHECK` is added later (slow lock). Or add with `NOT VALID`, then `VALIDATE CONSTRAINT` separately to avoid table lock.

## Generated columns

```sql
-- Stored generated column
CREATE TABLE products (
  id           uuid PRIMARY KEY DEFAULT uuidv7(),
  price_cents  bigint NOT NULL,
  price_rub    numeric(10,2) GENERATED ALWAYS AS (price_cents::numeric / 100) STORED
);

-- PG18 — virtual (default) generated columns
CREATE TABLE products (
  id          uuid PRIMARY KEY DEFAULT uuidv7(),
  price_cents bigint NOT NULL,
  price_rub   numeric(10,2) GENERATED ALWAYS AS (price_cents::numeric / 100)   -- virtual (default in 18)
);
```

PG18 makes virtual generated columns the default. They aren't stored; they're computed on read. Faster writes, slower reads. Use STORED when indexing the generated value.

## Foreign keys — index them

Postgres does NOT automatically index foreign-key columns. Every FK column should have an index:

```sql
CREATE INDEX orders_user_id_idx ON orders (user_id);
```

Without it, parent-row delete/update triggers full-table scans of the child.

## Partial unique indexes (soft delete)

```sql
CREATE UNIQUE INDEX users_email_active_unique
  ON users (email)
  WHERE deleted_at IS NULL;
```

Email can be reused after soft-delete, but uniqueness still enforced among active rows.

## Composite primary keys

```sql
CREATE TABLE memberships (
  user_id uuid REFERENCES users(id) ON DELETE CASCADE,
  org_id  uuid REFERENCES organizations(id) ON DELETE CASCADE,
  role    text NOT NULL,
  PRIMARY KEY (user_id, org_id)
);
```

Note: order matters for the implicit B-tree index. Put the more-selective column first.

## Temporal constraints (PG18)

```sql
CREATE TABLE rentals (
  id      uuid,
  car_id  uuid,
  period  tstzrange NOT NULL,
  EXCLUDE USING GIST (car_id WITH =, period WITH &&)   -- pre-PG18
);

-- PG18 native:
CREATE TABLE rentals (
  id      uuid,
  car_id  uuid,
  period  tstzrange NOT NULL,
  PRIMARY KEY (car_id, period WITHOUT OVERLAPS)
);
```

## JSONB

```sql
CREATE TABLE events (
  id    uuid PRIMARY KEY DEFAULT uuidv7(),
  payload jsonb NOT NULL,
  ts    timestamptz NOT NULL DEFAULT now()
);

-- index a specific path
CREATE INDEX events_payload_user_id_idx ON events ((payload->>'user_id'));

-- general JSONB index (slower writes, supports any key)
CREATE INDEX events_payload_gin ON events USING GIN (payload jsonb_path_ops);
```

Use JSONB for genuinely schemaless data. If 80% of rows have the same shape, normalize.

## Arrays vs join table

```sql
-- Array — fast read, no FK enforcement
CREATE TABLE posts (
  id   uuid PRIMARY KEY,
  tags text[] NOT NULL DEFAULT '{}'
);
CREATE INDEX posts_tags_gin ON posts USING GIN (tags);
SELECT * FROM posts WHERE tags @> ARRAY['tech'];
```

vs join table — slower, but normalized:

```sql
CREATE TABLE post_tags (
  post_id uuid REFERENCES posts(id) ON DELETE CASCADE,
  tag     text NOT NULL,
  PRIMARY KEY (post_id, tag)
);
```

Pick array for small, capped tag lists. Pick join table when you need tag metadata (`created_at`, `creator_id`).

## Naming conventions

- `snake_case` table and column names (Postgres default)
- Plural table names (`users`, `orders`) — convention varies; pick one
- FK columns: `<table_singular>_id` (`user_id`, not `users_id`)
- Index names: `<table>_<col>[_<col>]_idx`
- Constraint names: explicit (`orders_user_id_fkey`) — Postgres auto-names are stable but cryptic
- Sequences: `<table>_<col>_seq`

Quote names ONLY when they contain capitals or reserved words. Avoid both.
