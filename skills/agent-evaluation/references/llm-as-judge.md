# LLM-as-Judge

When the correct answer is not a single string, use a separate LLM to evaluate the output against a structured rubric. LLM-as-judge enables scalable evaluation of open-ended outputs — but requires careful design to produce reliable scores.

## When to Use

Use LLM-as-judge when:
- The correct answer is open-ended (explanations, plans, summaries, code reviews)
- Human annotation is too slow or expensive for the eval volume needed
- String matching and embedding similarity are insufficient

Do not use as the sole evaluation method when:
- The task has a deterministic correct answer — use exact match or schema validation
- The judge model would have conflicts of interest (self-preference bias is real)
- The rubric is too vague for even humans to agree on

## Rubric Design

A rubric decomposes quality into measurable sub-dimensions with explicit level descriptors.

**Good rubric** (concrete, independently scorable):

```python
RUBRIC = """
Evaluate the agent's response on the following dimensions. Score each 1–5.

## Faithfulness (does the response only claim what the source documents support?)
5 — Every claim is directly supported by a cited source document
4 — All major claims are supported; minor elaboration without contradiction
3 — Most claims supported; 1-2 claims go beyond sources without contradiction
2 — Several unsupported claims; sources partially support the response
1 — Response contradicts sources or fabricates information not in sources

## Completeness (does the response address all parts of the question?)
5 — All aspects of the question are addressed with appropriate depth
4 — All aspects addressed; one is shallow
3 — Most aspects addressed; one is missing
2 — Half or more of the question is unaddressed
1 — Response fails to address the core question

## Coherence (is the response logically structured and easy to follow?)
5 — Clear structure, smooth transitions, easy to read
4 — Good structure with minor clarity issues
3 — Understandable but disorganized
2 — Hard to follow; ideas jump without connection
1 — Incoherent or self-contradictory
"""

JUDGE_PROMPT = """\
You are evaluating an AI assistant's response.

[Question]: {question}
[Retrieved Sources]: {sources}
[Response]: {response}

{rubric}

Output a JSON object with keys: faithfulness, completeness, coherence.
Each key maps to an integer 1–5. Add a brief (1-2 sentence) rationale per dimension.
"""
```

**Bad rubric** (vague, not independently scorable):
```
Rate the quality of the response from 1 to 10.
```

This produces noisy, biased scores that are hard to interpret or act on.

## Bias Types and Mitigation

### Self-preference Bias

LLMs tend to prefer outputs generated by the same model family.

**Mitigation**: use a different model family as judge. If evaluating Claude outputs, use GPT-4o as judge. If evaluating GPT-4o outputs, use Claude as judge.

### Verbosity Bias

Longer responses are rated higher even when they contain padding or repetition.

**Mitigation**: explicitly instruct the judge to score based on content, not length. Add a dimension for conciseness if relevant. For pairwise comparisons, balance length across options or explicitly call out the bias.

### Position Bias

In pairwise comparisons, the option presented first is rated higher more often.

**Mitigation**: run pairwise comparisons twice with options in reversed order. If the preferred option changes, flag as uncertain and escalate to human review.

### Sycophancy

The judge may inflate scores when the evaluated response aligns with common or expected answers.

**Mitigation**: chain-of-thought before scoring — instruct the judge to reason about what the ideal response should contain before reading the evaluated response.

```python
COT_JUDGE_PROMPT = """\
Before evaluating the response, first reason about what an ideal response would contain.

[Question]: {question}

Step 1: What are the key elements a complete, accurate, and well-reasoned response must include?
<ideal_elements>
[Your reasoning here]
</ideal_elements>

Step 2: Now read the actual response and score it against your ideal.

[Response]: {response}

{rubric}

Output JSON: {{"faithfulness": int, "completeness": int, "coherence": int, "rationale": str}}
"""
```

## Dual-Judge / Ensemble

Run two independent judges and use agreement as a confidence signal.

```python
from anthropic import Anthropic
from openai import OpenAI

anthropic_client = Anthropic()
openai_client = OpenAI()

def dual_judge_score(question: str, response: str, sources: str) -> dict:
    prompt = JUDGE_PROMPT.format(
        question=question, sources=sources, response=response, rubric=RUBRIC
    )

    # Judge 1: Claude
    claude_result = anthropic_client.messages.create(
        model="claude-opus-4-5",
        max_tokens=512,
        messages=[{"role": "user", "content": prompt}],
    )
    score_a = parse_scores(claude_result.content[0].text)

    # Judge 2: GPT-4o
    gpt_result = openai_client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        response_format={"type": "json_object"},
    )
    score_b = parse_scores(gpt_result.choices[0].message.content)

    # Compute agreement per dimension
    agreement = {
        dim: abs(score_a[dim] - score_b[dim]) <= 1  # within 1 point
        for dim in ["faithfulness", "completeness", "coherence"]
    }
    needs_human_review = not all(agreement.values())

    return {
        "score_a": score_a,
        "score_b": score_b,
        "agreement": agreement,
        "needs_human_review": needs_human_review,
        "ensemble_score": {
            dim: (score_a[dim] + score_b[dim]) / 2
            for dim in ["faithfulness", "completeness", "coherence"]
        },
    }
```

**Escalation rule**: if judges disagree by > 1 point on any dimension for more than 15% of cases, the rubric needs revision.

## Human Correlation Study

Periodically validate that LLM judge scores correlate with human judgment.

**Protocol**:
1. Sample 100–200 evaluations from production or eval sets
2. Have 2–3 domain-expert humans score using the same rubric
3. Average human scores to get ground truth
4. Compute Spearman rank correlation between LLM judge and human average

```python
from scipy.stats import spearmanr

def validate_judge_correlation(llm_scores: list[float], human_scores: list[float]) -> dict:
    corr, p_value = spearmanr(llm_scores, human_scores)
    return {
        "spearman_rho": corr,
        "p_value": p_value,
        "n_samples": len(llm_scores),
        "status": "acceptable" if corr >= 0.7 else "needs_revision",
    }
```

**Targets**:
- ρ ≥ 0.8: strong judge, deploy with confidence
- ρ 0.7–0.8: acceptable, monitor
- ρ < 0.7: rubric revision required before using judge for production decisions

Inter-annotator agreement among humans should also be measured (target Cohen's κ > 0.6). If humans cannot agree, the rubric is too ambiguous to evaluate automatically.

## Practical Tips

- **Dimension count**: 3–5 dimensions is ideal. More dimensions degrade scoring accuracy (the judge's attention dilutes across too many criteria).
- **Score scale**: 1–5 is more reliable than 1–10. Fewer buckets reduce noise.
- **Temperature**: always use temperature=0 for judge calls to maximize reproducibility.
- **Model choice**: use the strongest available model as judge; judge quality is the ceiling of eval quality.
- **Cost**: judge calls are often as expensive as the evaluated calls. Budget accordingly.
