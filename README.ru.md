## Описание проекта

**Antigravity for Claude Code** — это специализированный MCP-сервер, выступающий интеграционным мостом между **Claude Code** (через кастомный агент `dev-orchestrator-test`) и консольным клиентом **Antigravity CLI** (`agy`), работающим на базе моделей Google Gemini.

Сервер позволяет перенаправлять сложные задачи разработки (выполнение YAML-контрактов на изменение кода) из Claude Code в Antigravity. Агент `agy` подгружает локально сохраненные скиллы (такие как `coder-craft` и `orchestrator-workflow`), точечно модифицирует файлы, запускает локальные тесты и возвращает структурированный результат.

Кроме того, сервер добавляет инструменты **автоматических дебатов (deliberation)** между ИИ-агентами с разными ролями, а также быстрый аудит изменений кода и выдачу технических советов.

## Доступные инструменты (MCP Tools)

1. **`discuss_with_antigravity`** — передает YAML-контракт задачи агенту `agy`. Тот выполняет его в локальном git-ворктри, прогоняет верификацию и возвращает отчет.
2. **`run_debate_deliberation`** — симулирует обсуждение архитектурных или бизнес-решений панелью экспертов с ролями:
   * **Optimist** (ищет плюсы, предлагает смелые решения)
   * **Skeptic** (проверяет гипотезы на прочность, ищет риски)
   * **Agreer** (ищет компромисс, сглаживает углы)
   * **Hater** (жестко критикует, указывает на явные баги)
   * **Synthesizer** (собирает выводы в единый консенсус-план)
3. **`review_code_changes`** — проверяет git diff на предмет багов, уязвимостей и стиля (P0/P1 критические ошибки, P2 рефакторинг).
4. **`get_programming_advice`** — выдает быстрые архитектурные советы и примеры реализации без сохранения контекста диалога.

## Реальный кейс использования (Case Study)

### Как автор проекта (Кирилл) использует эту связку в повседневной разработке:

#### Шаг 1. Постановка задачи и оценка сложности
Когда Кириллу нужно разработать новую фичу или исправить баг, он запускает интерактивное меню Claude Code командой `cc` (или напрямую тестовый оркестратор через алиас `ccdt`). Оркестратор запускает `Phase 0` (оценку сложности задачи по шкале от 0 до 11+ баллов) и создает детальный план в виде YAML-контрактов, которые записываются в локальную SQLite-базу данных `.claude/orchestrator.db`.

#### Шаг 2. Диспетчеризация задач (Dispatch)
Вместо того чтобы запускать стандартных субагентов Claude Code, тестовый оркестратор (`dev-orchestrator-test`) находит задачи с назначением `worker-coder` и отправляет их в MCP-инструмент `discuss_with_antigravity`.

#### Шаг 3. Исполнение в Antigravity (`agy`)
Antigravity получает YAML-контракт в изолированном контексте:
1. `agy` инициализирует скилл `coder-craft`, содержащий строгие правила: писать минимальный код, не делать лишних абстракций, сохранять стиль окружающего кода и не превышать лимиты строк (до 250 строк для TS).
2. Создается локальный git-worktree (например, `.worktrees/feat-auth-fix/`), и база данных `.claude/orchestrator.db` симлинкуется внутрь него.
3. `agy` производит хирургические правки кода только в разрешенных файлах.

#### Шаг 4. Локальная проверка и автодеплой
После того как `agy` завершает работу над контрактом, оркестратор:
1. Запускает тесты локально (например, `bun test` или `pytest`).
2. В случае успеха проводит автодеплой: делает слияние (`merge`) ветки в `main`, пушит на GitHub, билдит проект и мягко перезапускает процессы через PM2 (`pm2 reload`).
3. Если тесты упали — запускается цепочка автономного восстановления (recovery chain), которая скармливает ошибки обратно в `agy` для исправления без участия Кирилла.
