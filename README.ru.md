# Antigravity for Claude Code

**Превращает кодинг-агента Google Antigravity (на базе Gemini) в исполнителя для Claude Code от Anthropic. MCP-сервер, через который Claude Code делегирует реальное программирование, дебаты и код-ревью утилите `agy` — под управлением агента-менеджера, который планирует, раздаёт задачи, проверяет и выкатывает. В комплекте 16 скиллов разработчика и оркестраторы с автопилотом прямо в ветке `main`.**

## Что это такое?

Это MCP-сервер, который связывает **Claude Code** с консольным клиентом **Antigravity CLI** (`agy`, на базе Google Gemini) — так два кодинг-агента работают в команде.

Вместо того чтобы делать всю тяжёлую правку самому (или гонять собственных медленных субагентов), Claude Code работает как **проджект-менеджер**: оценивает задачу, пишет план и **отдаёт само программирование в `agy`** одним MCP-вызовом. Antigravity подгружает локальные скиллы (например, `coder-craft` и `orchestrator-workflow`), правит файлы, гоняет тесты и возвращает результат. Claude Code затем проверяет, ревьюит и выкатывает.

Помимо делегирования есть инструменты для **многоролевых ИИ-дебатов** (структурированные обсуждения с итоговым ADR), автоматического **код-ревью** на русском и быстрых **технических советов**.

### Что вы получаете

- 🧑‍💼 **Агенты-оркестраторы** — Claude Code как PM: планирует → раздаёт → проверяет → выкатывает, сам продакшен-код не пишет.
- 🤝 **Реальное делегирование** — тяжёлый код уходит в Gemini через `agy`, результат возвращается по MCP.
- 🧠 **16 скиллов разработчика** — правила чистого кода, фронтенд-стек, тестирование и редактура для Gemini.
- 🗣️ **Дебаты и ревью** — автономные или интерактивные обсуждения нескольких ролей, аудит кода, быстрые советы.
- 🛡️ **Хуки качества** — блокируют `@ts-ignore` и инлайновые HEX-цвета ещё до записи на диск.
- 🚀 **Автопилот в `main`** — агент `dev-orchestrator-agy` работает прямо в `main`, коммитит по задаче и авто-деплоит, когда все проверки зелёные.
- ⏱️ **Надёжный мост** — корректный жизненный цикл дочернего процесса (без зависаний), замер времени и футер `files_changed` в каждом ответе.

## Схема работы

```
┌──────────────────────────────────────────────────────────┐
│                      Claude Code                          │
│        (dev-orchestrator-agy — агент-менеджер)           │
│  оценка → план → раздача → проверка → ревью → выкат       │
└──────────────────────────┬───────────────────────────────┘
                           │  MCP: discuss_with_antigravity
                           │  (YAML-контракт + роль)
┌──────────────────────────▼───────────────────────────────┐
│                  Antigravity MCP Server                   │
│   запуск agy (detached, под таймаутом), разбор ответа     │
└──────────────────────────┬───────────────────────────────┘
                           │  agy --print  (промпт через stdin)
┌──────────────────────────▼───────────────────────────────┐
│                   Antigravity CLI (agy)                   │
│   загрузка скиллов → правка файлов → тесты → ответ        │
└──────────────────────────────────────────────────────────┘
```

### Как «думает» оркестратор

Агент `dev-orchestrator-agy` гоняет цикл из 7 фаз, управляемый оценкой сложности:

1. **Фаза 0 — Оценка.** Эвристика (0–11+) выбирает путь: Express (один вызов), Brief, Full (SPEC + N контрактов) или Split (слишком крупно).
2. **Фазы 1–2 — Понять и спланировать.** Минимум вопросов, затем SPEC и набор YAML-контрактов в локальной базе SQLite (`.claude/orchestrator.db`).
3. **Фаза 3 — Подтверждение.** Работа идёт **прямо в `main`** — без worktree и фиче-веток.
4. **Фаза 4 — Раздача + восстановление.** Каждый готовый контракт уходит в `agy` по MCP; при сбоях включается автономная цепочка восстановления.
5. **Фазы 5–6 — Ревью и итерации.** По каждой задаче гоняются верификаторы (тесты, безопасность, платежи, UI); находки чинятся и перепроверяются.
6. **Фаза 7 — Выкат.** Финальный gate ревью, затем коммит + `git push origin main` (только fast-forward — force-push в main запрещён всегда) и авто-деплой.

За прогрессом можно следить из любого терминала: `task list`, `task show <id>`, `task logs <id>`, `task graph`.

## Структура репозитория

* `src/` — исходники MCP-сервера (TypeScript, сборка/запуск через Bun).
* `dist/` — скомпилированный сервер (под Node).
* `agents/` — оркестраторы: `dev-orchestrator-agy.md` (автопилот в `main`) и `dev-orchestrator.md`.
* `skills/` — 16 скиллов разработчика с правилами и инструкциями для Gemini.
* `examples/` — примеры подключения на TypeScript, Python, Go и Bash.
* `scripts/` — валидатор хуков (`validate-tool-call.cjs`) и хелперы.
* `CLAUDE.global.md` — пример глобального конфига правил для копирования в `~/.claude/CLAUDE.md`.
* `install-hooks.cjs` / `run-server.sh` — установщик хуков и запуск с изолированным окружением.

## Перенесённые скиллы (`/skills`)

Помогают Gemini работать как профессиональный разработчик, архитектор или дизайнер:

* **Базовые**: `coder-craft` (чистый код, хирургические правки, контроль лимитов строк), `karpathy-guidelines` (простота, отказ от лишних абстракций).
* **Рабочий процесс**: `orchestrator-workflow` (парсинг YAML-контрактов, работа с БД, авто-восстановление), `claude-code` (паттерны интеграции).
* **Фронтенд**: `frontend-craft`, `css-architecture-2026`, `design-system-2026`, `ux-craft-2026`, `web-animation-router`, `webgl-creative-2026`, `svg-canvas-craft`, `web-qa-2026`, `media-asset-pipeline`.
* **Тестирование и текст**: `pytest`, `vitest`, `ru-text-quick` (инфостиль, русская типографика, запрет ИИ-клише).

## Доступные MCP-инструменты

| Инструмент | Что делает |
|---|---|
| `discuss_with_antigravity` | Многошаговый диалог / делегирование задачи. Автоматически ловит ID задачи (`id: TASK-NNN`) из промпта для привязки контекста. Принимает `role` (`designer`, `copywriter`, `programmer`, `architect`). |
| `reset_antigravity_session` | Сброс активной сессии обсуждения из памяти. |
| `run_debate_deliberation` | Автономные дебаты нескольких ролей (Оптимист, Скептик, Адвокат дьявола…) с итоговым ADR. |
| `run_interactive_debate` | Интерактивные дебаты, где вы — Судья/Архитектор и направляете роли репликами, с финальным ADR. |
| `review_code_changes` | Код-ревью git-диффа или сниппета на русском (баги, безопасность, чистота кода). |
| `get_programming_advice` | Быстрый точечный совет по коду или архитектуре. |
| `get_debate_receipt` | Структурированный «чек дебатов» (Markdown): тезисы ролей, аргументы, отвергнутые альтернативы, изменённые файлы и данные аудита хуков. |

Каждый ответ `discuss`/`programming` дополнительно содержит футер с временем вызова и списком `files_changed` (по git) — всегда видно, что именно исполнитель тронул.

## Требования

- **[Claude Code](https://docs.claude.com/en/docs/claude-code)** — хост.
- **[Antigravity CLI](https://antigravity.google)** (`agy`) — установлен и **авторизован** (запустите один раз интерактивно для входа). Сервер вызывает `agy --print`.
- **[Bun](https://bun.sh)** ≥ 1.0 — для сборки и тестов сервера.
- **Node.js** ≥ 20 — для запуска скомпилированного `dist/index.js`.

## Установка и настройка

### 1. Сборка сервера
```bash
git clone https://github.com/VKirill/antigravity-for-claude-code.git
cd antigravity-for-claude-code
bun install        # или: npm install — запускает `prepare`, который сам собирает dist/
# (dist/ генерируется и НЕ коммитится; пересобрать в любой момент: bun run build)
```

### 2. Подключение сервера к Claude Code
Добавьте в `~/.claude.json` (укажите **абсолютный путь** к своему клону):
```json
{
  "mcpServers": {
    "antigravity": {
      "command": "node",
      "args": ["/АБСОЛЮТНЫЙ/ПУТЬ/к/antigravity-for-claude-code/dist/index.js"],
      "timeout": 1260000
    }
  }
}
```
> **Два режима запуска.** Конфиг выше запускает собранный бандл (`node dist/index.js`). Либо укажите в
> `command` путь к `run-server.sh` — он запускает сервер прямо из `src/` через Bun (**сборка не нужна**) и
> изолирует состояние `agy` каждого проекта в `~/.cache/antigravity-mcp/<хеш-проекта>/` (вне дерева
> проекта, чтобы агент не засасывал собственные логи/кэш обратно в контекст). В обоих случаях промпты
> подхватываются из папки `prompts/` репозитория автоматически (переопределяется `ANTIGRAVITY_PROMPTS_DIR`).

### 3. Установка агента-оркестратора
```bash
mkdir -p ~/.claude/agents
cp agents/dev-orchestrator-agy.md ~/.claude/agents/
```
Запуск внутри любой папки проекта:
```bash
claude --agent dev-orchestrator-agy
```
Агент отдаёт 100% кодинга/верификации в Antigravity MCP с подобранными ролями и промптами лучших практик 2026 года. Работает прямо в `main` и авто-деплоит, когда все проверки зелёные.

### 4. (Опционально) Глобальные правила работы
```bash
cp CLAUDE.global.md ~/.claude/CLAUDE.md
```
Задаёт разумные дефолты для всех проектов и описывает политику авто-пуша в `main`, на которую опирается оркестратор. **Отредактируйте секции «Server environment» и «Context» под себя.**

### 5. Установка скиллов разработчика
```bash
mkdir -p ~/.gemini/antigravity/skills
cp -r skills/* ~/.gemini/antigravity/skills/
```

### 6. Установка хуков качества (рекомендуется)
```bash
bun run install-hooks   # или: npm run install-hooks
```
Делает валидатор исполняемым и прописывает его в `~/.gemini/antigravity-cli/hooks.json` с корректным абсолютным путём. Блокирует `@ts-ignore` / `@ts-nocheck` и хардкод HEX-цветов в Vue/CSS.

## Конфигурация (переменные окружения)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AGY_TIMEOUT_MS` | `1200000` | Жёсткий таймаут (мс) вызова `agy`. При таймауте убивается вся группа процессов, вызов падает без повтора (чтобы не прогонять полу-готовые правки). Из него же выводится `--print-timeout` для `agy` (`значение/1000 − 20с`). |
| `AGY_EXIT_FALLBACK_MS` | `1500` | Запас (мс) после выхода процесса перед тем, как мост принудительно вернёт накопленный вывод — спасает от зависаний, когда движок `agy` держит канал открытым. |

> **Слои таймаутов.** Три лимита складываются и должны идти по порядку:
> `agy --print-timeout  <  AGY_TIMEOUT_MS  <  таймаут MCP-тула в Claude Code`.
> Самый внешний (сколько Claude Code ждёт ответ тула) **этот сервер не задаёт**. Глобальный дефолт
> Claude Code `MCP_TOOL_TIMEOUT` = **600000 мс (10 мин)** — это *ниже* дефолта `AGY_TIMEOUT_MS` выше,
> поэтому его надо поднять. Предпочтительно — задать **per-server** поле `timeout` (мс) в записи
> `mcpServers` (см. шаг 2 установки — оно скоупит только сервер antigravity и покрывает ожидание ответа
> тула). Ставьте его чуть выше `AGY_TIMEOUT_MS` (например `1260000`), чтобы первым сработал наш чистый
> таймаут с group-kill. Глобальный env `MCP_TOOL_TIMEOUT` тоже работает, но влияет на все MCP-серверы.

## Кейс из практики

### Как автор (Кирилл) использует это в работе

#### 1. Планирование и контракты
Для сложных задач Кирилл запускает оркестратор. Тот оценивает сложность, декомпозирует задачу и записывает план в локальную базу `.claude/orchestrator.db` в виде YAML-контрактов.

#### 2. Передача работы в Antigravity
Оркестратор берёт задачи, назначенные исполнителю `worker-coder`, и отправляет их в `discuss_with_antigravity` с нужной ролью.

#### 3. Разработка в `agy`
Antigravity берёт задачу и обрабатывает её по скиллу `coder-craft`:
1. Вносит точечные правки **прямо в ветке `main`**, соблюдая стиль окружающего кода.
2. Делает по одному коммиту на задачу — история остаётся читаемой.
3. Не выходит за лимиты строк (например, до 250 строк на файл для TS).

#### 4. Тестирование и деплой
После правок оркестратор гоняет тесты (например, `bun test`):
* **Зелёные** → финальный gate ревью, затем `git push origin main` (только fast-forward), сборка и `pm2 reload`.
* **Красные** → цикл самовосстановления: ошибки уходят обратно в Gemini на исправление.
